# PageTrace — limitations and known gaps (T013)

This file states what PageTrace cannot do, what the S0 gate does not
cover, and the known divergences left over from the T012 independent
review. Nothing here is a secret: if a capability is not listed in
`README.md`, assume it does not exist.

## Capability boundaries

- **No OCR.** Text that exists only as a raster image is invisible to
  the tool. Such quotes are `FAIL_UNLOCATABLE`, never "not in the
  document".
- **No semantic fact-checking.** PageTrace checks page *identity*
  (does the cited page match the page where the normalised quote was
  found?), not whether the quoted words are true, complete, or fairly
  attributed.
- **Exact matching only.** A quote that differs by one character from
  the page text is a near miss (`NO_EXACT_MATCH`), not a match. There
  is no fuzzy matching.
- **Single-document, offline, local files only.** No network access,
  no fetching, no external service calls. PDFs are capped at 50 MiB /
  500 pages by default (limits can only be lowered).
- **No claim about real systems.** S0 passing means the tool behaves
  correctly on the 48 frozen synthetic fixtures. It is not evidence
  that any real-world pipeline (a specific reader app, indexer, or
  viewer) has passed, and the README makes no such claim.

## S0 coverage gaps (T012 P2-07)

- The frozen 48-case suite exercises only fault verdicts
  (`FAIL_*`, 4 classes × 12) and `PASS`. It contains **no**
  `AMBIGUOUS` / `UNKNOWN_*` / `NEEDS_MANUAL_REVIEW` citation, so S0
  never exercises the uncertainty paths. Those paths are covered only
  by unit/integration tests (14 references in the test suite).
- The Oracle's triple-span probe (`tests/oracle/locate.py`
  `_triple_spans`) is a **bounded subset** of production's exhaustive
  `_spans_triple`: it tries only `prefix_max-3..prefix_max` ×
  `suffix_max-3..suffix_max` splits. A triple-span quote whose true
  split lies outside that window would be found by production
  (`unsupported_span` → `NEEDS_MANUAL_REVIEW`) and missed by the
  Oracle (`FAIL_UNLOCATABLE`). No such input exists in the frozen
  suite (all specs have `split_pages0` of length 0 or 2, never 3).
  Do NOT "fix" this by adding a 3-page fixture — the suite is frozen.

## Known production↔Oracle divergences

- **P2-04 (open, production-only fix).** An out-of-range display value
  (e.g. `PDF_NUMBER_1` value `0`) reports reason
  `VALUE_OUT_OF_RANGE` in production but `VALUE_BASIS_TYPE_MISMATCH`
  in the Oracle (`tests/oracle/attribute.py:579-586`). The verdict
  (`NEEDS_MANUAL_REVIEW`) agrees. `reason` is not an S0 parity field,
  so the gate is unaffected. Left divergent deliberately: the Oracle
  is an independent implementation and is not silently edited to match
  production.
- **P2-05 (closed by T013).** Production and the Oracle now both set
  `reason="TRACE_MISSING"` for `UNKNOWN_TRACE_MISSING` (the Oracle
  used to leave it null). Pinned by a parity test.

## Records, not fixes (frozen spec — not changed)

- **P2-10 — `fixtures build` is not implemented.** PROJECT_BOOK §12.1
  shows `python -m pagetrace.cli fixtures build --out
  fixtures/generated`, but the CLI has only analyze / validate / s0 /
  clean. The 48 fixtures are frozen T002 products, not generated by
  the CLI. Implementing the command needs its own task; see
  `docs/CLI.md` ("未实现：`fixtures build`").
- **P2-11 — UN attribution (un-ext-09..12), FIXED by FIX-R1 P1-R1-02.**
  GPT final review R1 found the near-miss `UNLOCATABLE` cases wrongly
  blamed `extraction`: production, Oracle and Golden all returned
  `first_fault_stage = "extraction"` (and `expected_source_pages0`
  = the trace-claimed page) even when the extraction records matched
  the honest extraction exactly and the only defect was a one-character
  quote difference (`NO_EXACT_MATCH`). New rule, applied identically
  in production (`src/pagetrace/compare_stages.py`), Oracle
  (`tests/oracle/attribute.py`) and Golden
  (`fixtures/golden/expected.json`): extraction is blamed only for a
  provable extraction failure — anchor page honestly `IMAGE_ONLY` /
  `EMPTY`, or a bundle extraction record for a claimed page that
  provably differs from the honest extraction. Otherwise
  (`NO_EXACT_MATCH` / `NO_TEXT_LAYER` with verified-correct
  extraction) `first_fault_stage` is `null` and
  `expected_source_pages0` is `null`: the trace-claimed page is
  unconfirmed, never a verified source. `null` is the existing
  report-schema convention for "no stage can be blamed" (same as
  `PASS` / `UNKNOWN_TRACE_MISSING` / `AMBIGUOUS` /
  `NEEDS_MANUAL_REVIEW`). Affected cases: `un-ext-09..12` (the four
  `NO_EXACT_MATCH` cases); `un-ext-01..08` (`IMAGE_ONLY` / `EMPTY`)
  still blame `extraction`. Full record:
  `07_evidence/runtime_logs/FIX_R1_UNLOCATABLE.md`.
- **P2-11 residual — UN §8.1 composition wording (un-ext-12 only).
  RESOLVED by FIX-R1收尾.** The frozen spec says the 12 UN cases
  "均含扫描件式图像页或无文本层页面"; `un-ext-12` previously had
  8 all-`TEXT` pages. The generator was fixed
  (`tools/generate_fixtures.py`: near-miss UN cases are guaranteed a
  non-text page on a free page that is neither an anchor nor part of
  the control citation) and fixtures `un-ext-09..12` were regenerated
  (other 44 cases byte-identical): `un-ext-12` now has page index 6
  `EMPTY` (page states `TEXT`×6, `EMPTY`, `TEXT`; anchor page index 5
  still `TEXT`, control citation pages 0–1 untouched), its page-0
  header no longer claims a definite stage, and all 12 UN cases now
  contain at least one image or blank page. Full record:
  `07_evidence/runtime_logs/FIX_R1_UNLOCATABLE.md` §8.

## Installed-package notes

- The installed wheel's `s0` subcommand requires a source checkout:
  `tools/run_s0.py`, `fixtures/` and the Oracle are development
  artefacts and are not shipped in the wheel. `analyze`, `validate`
  and `clean` work from an installed wheel.
- `clean` prints the target path exactly as given (T013 P2-01); the
  resolved absolute path is used only for internal checks. Error
  messages likewise echo the given path.
- The frozen schemas ship inside the installed package
  (`src/pagetrace/schemas/`, byte-identical to `contracts/`). If the
  two copies ever differ, that is a defect — a test pins them identical.
